# dsh-beacon v2.1.1

固件 2.1.1，电脑端插件 dsh-led-bridge 2.1.0。

## 修复内容

- 修复打开配网页时，旧时间戳与 HTTP 回调的新时间戳相减发生无符号下溢，误触发空闲重启的问题。保存网络、清除配置、模式切换和空闲恢复不再主动重启。
- Wi-Fi 扫描结果直接显示为可点击的网络名称按钮，合并同名接入点，保留手动输入。修复扫描计时与连续连接失败后的配网恢复。
- 配网页使用 Flash 静态内容，管理操作限制到 USB 串口，保留框架欠压保护。
- 插件修复工具和审批状态、多个会话的状态聚合、断线重连后的状态同步及异步写入错误处理。
- 重写 README，补充接线、烧录、USB/TCP 配置和排障说明。

## 下载与烧录

默认选择普通版；最小版只有手动输入网络的页面，可用于对照排查。

| 附件 | 烧录地址 | 用途 |
| --- | --- | --- |
| `dsh-beacon-v2.1.1-full.bin` | `0x0` | 普通版完整镜像，首次安装使用 |
| `dsh-beacon-v2.1.1-app.bin` | `0x10000` | 普通版应用更新 |
| `dsh-beacon-v2.1.1-minimal-full.bin` | `0x0` | 最小版完整镜像 |
| `dsh-beacon-v2.1.1-minimal-app.bin` | `0x10000` | 最小版应用更新 |
| `dsh-led-bridge-2.1.0.tgz` | — | 插件源代码包，不含 node_modules |
| `SHA256SUMS.txt` | — | 以上文件及 `FLASHING.md` 的 SHA-256 校验值 |
| `FLASHING.md` | — | 本说明的离线副本 |

**完整镜像覆盖 4 MB Flash，会清除已有 Wi-Fi 配置及配网密码。应用镜像不能烧到 `0x0`。** 应用更新仅适用于相同板型、Flash 和分区配置；否则使用完整镜像。

构建环境：Arduino CLI 1.3.1 / Arduino-ESP32 3.3.11，ESP32C3 Dev Module，CPU 80 MHz，4 MB Flash，DIO / 40 MHz，默认分区，USB CDC on boot 开启。已验证硬件为 ESP32-C3 QFN32 revision v0.4、XMC 4 MB Flash、原生 USB Serial/JTAG。

关闭占用串口的程序，将下例 `COM4` 替换为实际端口。使用 esptool 5.x：

```powershell
esptool --chip esp32c3 --port COM4 --baud 460800 write-flash --flash-mode dio --flash-freq 40m --flash-size 4MB 0x0 dsh-beacon-v2.1.1-full.bin
```

相同分区下只更新应用：

```powershell
esptool --chip esp32c3 --port COM4 --baud 460800 write-flash --flash-size 4MB 0x10000 dsh-beacon-v2.1.1-app.bin
```

最小版将文件名替换为对应的 `minimal` 镜像。连接不稳定时可将波特率改为 115200。使用图形烧录工具时，同样按上表填写镜像地址，设置 DIO、40 MHz、4 MB。

下载后可在 PowerShell 中计算校验值，与 `SHA256SUMS.txt` 比较：

```powershell
Get-FileHash .\dsh-beacon-v2.1.1-full.bin -Algorithm SHA256
```

## 配网密码与使用

公开固件没有固定配网密码，不包含本地测试设备的密码。设备首次进入配网时生成并将随机密码保存到 NVS；应用更新保留已有密码。

1. USB 连接设备，用串口监视器打开实际端口，波特率 115200。
2. GPIO4 接 GND 为 Wi-Fi 档；断开为 USB 档。首次安装没有网络配置，进入 Wi-Fi 档后会打印 `CONFIG AP=DSH-Beacon-XXXX password=...`。若错过该行，将开关切到 USB 档，再切回 Wi-Fi 档。
3. 用打印的密码连接 ESP 热点，打开 `http://192.168.4.1/`，扫描或手动输入目标 2.4 GHz 网络，然后保存。
4. 接入目标网络后 ESP 配网热点会关闭。连接连续失败约 15 秒后回到配网模式。已有网络配置时如需重新配网，可在 USB 串口发送 `wifi clear` 清除凭据。
5. 关闭串口监视器后再使用 Harness 插件。TCP 模式下，电脑应能访问设备所在网络；目标地址是设备接入网络后的地址，可通过串口 `wifi?` 查询。

分享串口日志前隐藏密码。插件源代码包解压后在其 `package.json` 所在目录运行 `npm install`，再按 [README](https://github.com/Rrttttttt/dsh-beacon/blob/v2.1.1/README.md) 将该目录加入实际 Harness profile；也可直接克隆仓库并使用 `npm ci`。

引脚：红 GPIO5、黄 GPIO6、绿 GPIO7；默认共阳 LED 公共端接 3V3、低电平点亮，每路需要限流电阻。其他接法需要修改源代码并自行编译。

## 验证范围

修复代码已通过 23 项 Node 测试、两组 C++ 回归测试和普通/最小版编译；用户已确认 USB 连接下配网访问、扫描界面及网络连接的实物验证通过。本 Release 两套固件使用设备生成密码选项重新编译，未追加烧录测试。

IP5306 供电专项复测、长期稳定性、同网 TCP 实物验收和实际 Harness 集成仍未完成。

可重建附件对应固件：

```powershell
./scripts/Build-Firmware.ps1 -Release
./scripts/Build-Firmware.ps1 -Release -MinimalConfig
```

输出目录为 `.build/firmware-release/` 和 `.build/firmware-minimal-release/`。完整镜像对应 `esp32c3_dsh_status_light.ino.merged.bin`，应用镜像对应 `esp32c3_dsh_status_light.ino.bin`。
